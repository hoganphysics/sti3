# Legacy XML Documentation of Shots and Sequences

- The STIServer is responsible for generating XML documentation for parse results, experimental shot results, and sequences.
- All XML files are stored in a designated directory on the server.

- For each shot, the server creates a shot XML
  - The shot XML files contain detailed information about the shot played, including:
    - title containing the ShotID
    - date (timestamp of when the shot was played)
    - A list of python filenames consisting of the timing file scripts used to generate the shot
    - The list of Devices used in the shot. For each Device, include:
        - DeviceID information
        - Attributes data for the device (as key-value pairs)
        - Measurements made by the device during the shot
    - The list of ParsedVar variables used in the shot and their values
  - The experiment XML files are generated for each shot are built by the LegacyExperientXMLBuilder class.
  - The LegacyShotRepository plugs into the sti3 library and is used by the library to generate the shot XML files.
    - The sti3 library calls LegacyShotRepository::saveShot to save the shot XML file.

- The server also generates parse XML files associated with the shots.
  - Before a shot can be played, the shot must be parsed.
  - Parsing a shot configures the event engines and results in the creation of a ParseResult object by the sti3 library. 
    - The ParseResult object contains information about the devices and configurations used in the shot.
  - When a shot is later played and saved, the LegacyShotRepository saves the parse XML file using the ParseResult object (in addition to saving the shot XML file).
    - If multiple shots are played using the same parsed shot (same ParseResult and ParseID), the parse XML file is only saved once, when the first shot is saved.
    - The shot XML files should reference the associated parse XML file (multiple shot XML files can reference the same parse XML file).
  - The parse XML files contain all of information in the ParseResult object, including:
    - title containing the ParseID
    - date (timestamp of when the shot was parsed)
    - ShotConfig information used to parse the shot (the data in the ShotConfig object)
    - Event data stored in the RawEventGroup object (baseEventGroup in ParseResult)
      - RawEvents
      - ParsedVars
      - ParsedTags
      - subgroups (including their events and variables, etc)
      - metadata
    - The ParsedDependencyTree object (dependencyTree in ParseResult) representing the dependencies between devices and events in the shot.
    - The list of EngineParsingMessages (engineMessages in ParseResult) generated during the parsing of the shot.
    - The data in the StackTraceResult object (stackTraceResult in ParseResult) representing the stack trace information if any errors occurred during parsing.
  - To allow for reloading of parse XML files, the LegacyShotRepository should also implement a getParseResult method to read parse XML files back into a ParseResult object.
    - This can be implemented using the existing cereal serialization framework used in sti3, which supports serialization and deserialization of complex objects to and from XML format.
  - The LegacyShotRepository plugs into the sti3 library and is used by the library to generate the parse XML files.
    - The sti3 library calls LegacyShotRepository::saveShot to save the shot and parse XML file, as needed.

- For sequences, the server plays a series of shots.
  - Each shot in the sequence has its own parse file and shot file as described above.
    - If the a shot uses the same ParseResult (same ParseID) as a previous shot, the same parse XML file is referenced and a new parse XML file is not created.
  - Additionally, the server generates a sequence XML file for each sequence played.
    - The sequence XML file contains information about the sequence as a whole and links to the individual shot XML files.
    - The sequence XML should be updated each time a new shot is added to the sequence.
  - The sequence XML file contains:
    - title containing the SequenceID
    - date (timestamp of when the sequence was played)
    - The list of experiment shots included in the sequence. Each entry includes:
      - The set of overriden variables and their values used for the shot
      - Link to the associated shot XML file via relative path
  - The sequence XML files are generated by the LegacySequenceXMLBuilder class
